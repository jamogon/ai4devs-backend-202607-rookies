Analiza este proyecto y explícamelo como si acabara de entrar en el equipo hoy.

No escribas código. No arregles nada. Solo entiende y cuenta.

Cubre, en este orden:

1. **Qué hace este proyecto** y quién lo usa. Una frase.
2. **Cómo está organizado el backend.** Las capas reales, con un fichero de
   ejemplo de cada una. Si el README dice algo que no existe, dilo.
3. **Qué patrón usan los modelos** para hablar con la base de datos, con un
   ejemplo concreto.
4. **Las convenciones que se deducen del código**: naming, manejo de errores,
   validación. Y **cuáles se incumplen** en el propio repo.
5. **Qué NO existe** aunque parezca que debería: capas ausentes, tests,
   infraestructura de errores.
6. **Trampas.** Cosas que harían perder una tarde a alguien nuevo. Comandos del
   README que fallan, configuración duplicada, ficheros que no se ejecutan.

Para cada afirmación, **fichero y línea**. Si no lo has comprobado, no lo digas.

Termina con las tres cosas que le contarías a alguien que empieza mañana.
